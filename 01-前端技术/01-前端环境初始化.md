## 📂 第一步：颗粒化目录树与一键创建

在现代工程中，代码和它的测试文件“形影不离”，这种颗粒化管理（Colocation）对大项目和 AI 工具极其友好。整个 `src` 目录的最终形态如下：

```text
src/
├── api/                    # [接口层] 按模块统一管理 Axios 请求
│   └── product.ts
├── assets/                 # [资源层] 静态资源与全局样式
│   ├── images/             # 仅存放极小的 UI 图标/Logo
│   └── styles/
│       └── main.css        # Tailwind v4 + Nuxt UI 主样式文件
├── components/             # [组件层] 抽离的可复用公共组件
│   ├── common/             # 通用微型组件
│   └── layout/             # 布局组件
├── composables/            # [逻辑层] 封装的组合式业务 Hooks
├── router/                 # [路由层] 路由配置中心
│   └── index.ts
├── stores/                 # [状态层] Pinia 全局状态
├── types/                  # [类型层] TS 类型声明
├── utils/                  # [工具层] 纯工具函数
│   ├── __tests__/          # 工具函数的单元测试目录
│   ├── http.ts             # Axios 实例及拦截器
│   └── format.ts           # 价格/时间格式化
├── views/                  # [视图层] 页面级组件（严格遵守多单词规范）
│   ├── Home/               # 首页模块
│   │   ├── __tests__/      # 首页专属测试目录（就近存放）
│   │   │   └── HomeView.spec.ts
│   │   └── HomeView.vue    # 首页组件
│   ├── Cart/               # 购物车模块
│   └── Profile/            # 个人中心模块
├── App.vue                 # 根组件容器
└── main.ts                 # 项目全局入口

```

### 2. 路由配置：`src/router/index.ts`

采用标准规范的 `*View` 后缀进行组件引入：

```typescript
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '@/views/Home/HomeView.vue'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'home',
      component: HomeView
    },
    {
      path: '/cart',
      name: 'cart',
      component: () => import('@/views/Cart/CartView.vue')
    }
  ]
})

export default router

```

### 3. 网络请求：`src/utils/http.ts`

基于 Axios 封装的统一联调底座，预留了解包与全局错误处理逻辑：

```typescript
import axios from 'axios'

const http = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 10000,
  headers: {
    'Content-Type': 'application/json'
  }
})

// 请求拦截器
http.interceptors.request.use(
  (config) => {
    return config
  },
  (error) => Promise.reject(error)
)

// 响应拦截器
http.interceptors.response.use(
  (response) => {
    // 自动解包数据流
    return response.data
  },
  (error) => {
    if (error.response?.status === 401) {
      console.error('全局拦截：登录状态已失效，请重新登录')
    }
    return Promise.reject(error)
  }
)

export default http

```

### 5. 全局入口：`src/main.ts`

> ⚠️ **注意**：Nuxt UI v3 采用极其先进的 Unplugin 自动引入架构，**不要**在入口文件中写 `app.use(ui)`，Vite 插件会自动托管一切。

```typescript
import './assets/styles/main.css' // 引入全局样式

import { createApp } from 'vue'
import { createPinia } from 'pinia'

import App from './App.vue'
import router from './router'

const app = createApp(App)

app.use(createPinia()) // 挂载状态
app.use(router)      // 挂载路由

app.mount('#app')

```

## 🛠️ 第三步：外部配套依赖检查

为了确保 Nuxt UI 自动生成的组件声明能够被编译器完美识别，请确保你项目根目录下的 **`vite.config.ts`** 和 **`tsconfig.app.json`** 的相关配置如下：

### `vite.config.ts` 的标准形态：

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite' // 确保引入了该打包插件

export default defineConfig({
  plugins: [
    vue(),
    ui() // 挂载它，它负责自动按需注册组件
  ],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  }
})

```

### `tsconfig.app.json` 文件的 `include` 补全：

```json
{
  "compilerOptions": {
    // 保持原有配置
  },
  "include": [
    "src/**/*.ts",
    "src/**/*.tsx",
    "src/**/*.vue",
    "auto-imports.d.ts", // 确保包含自动生成的文件
    "components.d.ts"    // 确保包含自动生成的文件
  ]
}

```
