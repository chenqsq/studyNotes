## 🚀 现代化 Vue 3 项目日常开发与维护指南

---

### 一、 日常开工三步走 (Daily Routine)

每天开始写代码前，或者从 Git 仓库拉取最新代码后，标准的执行流水线如下：

1. **同步依赖环境**：
```bash
pnpm i

```


*作用：确保你的本地 `node_modules` 与配置文件完全一致，防止别人加了新包而你本地跑不起来。*
2. **启动开发服务器**：
```bash
pnpm dev

```


*作用：启动 Vite 极速热更新服务，点击终端给出的 `http://localhost:5173` 开始视觉联调。*
3. **（可选）开启测试监听**：
```bash
pnpm test:unit

```


*作用：Vitest 默认是监听模式（Watch Mode）。单独开一个终端小窗口挂着它，当你改动业务代码时，它会在后台自动秒级重跑对应的 `.spec.ts`，实现“边写边测”。*

---

### 二、 标准业务功能开发流 (Feature Pipeline)

当你拿到一个新的 Figma 视觉稿（例如：开发“商品详情页”）时，请严格按照以下“解耦流水线”进行编码，这是大厂正规军的核心心法：

```text
【图纸定义】types/product.ts ──> 定义后端返回的数据结构
      │
【网络封装】api/product.ts   ──> 封装 Axios 接口请求
      │
【积木组装】components/     ──> 编写局部可复用小组件
      │
【页面拼装】views/Product/   ──> 拼成完整的 ProductDetailView.vue 页面
      │
【颗粒质检】__tests__/       ──> 在同级目录下编写单元测试

```

> **🔥 独立开发提效秘籍 (配合 AI 调试)**：
> 在使用 Cursor 或 v0.dev 辅助生成页面时，先不要盲目让它直接画页面。**第一步先把 `types/` 里的数据结构喂给它**，有了严格的类型约束后，AI 帮你写出来的 API 请求和 Vue 组件，幻觉率会降低 80% 以上。

---

### 三、 代码提交前置质检 (Pre-commit Check)

在准备将代码提交到 Git 仓库，或者准备打包发布之前，必须在终端依次运行以下三条质量铁律：

1. **超高速语法纠错**：
```bash
pnpm lint

```


*作用：项目配置了基于 Rust 编写的 `oxlint`。它会在几毫秒内闪电般扫完所有文件，抓出隐藏的代码逻辑错误，随后交由 `eslint` 做深度校验。如果有红线报错，必须修完才允许推代码。*
2. **全局代码大美容**：
```bash
pnpm format

```


*作用：调用 Prettier 按照团队最严苛的格式化标准，一键对齐所有空格、换行、单双引号，确保代码整洁度如同一个人写出来的。*
3. **回归测试（防葫芦塌陷）**：
```bash
pnpm test:unit

```


*作用：确保你今天为了修 A 功能的代码，没有意外搞砸 B 功能。必须拿到全绿通行证。*

---

### 四、 生产打包与运维部署 (Build & Deployment)

当首页切图完成、接口联调完毕，需要发布到线上（如通过 1Panel 或 Docker 部署）时，执行以下发布流：

#### 1. 检查环境变量

在根目录下建立 `.env.production` 文件，配置生产环境的后端 API 真实地址（防止打包进了本地的 localhost）：

```env
VITE_API_BASE_URL=https://api.yourdomain.com

```

#### 2. 执行打包构建

```bash
pnpm build

```

*构建成功后，项目根目录下会生成一个名为 `dist/` 的文件夹。里面全是经过极致压缩、混淆、静态化的 HTML、JS 和 CSS 文件。*

#### 3. 运维合规检查

* **端到端终极防线**：在正式上线前，执行 `pnpm test:e2e`。Playwright 会在后台静默打开真实的 Chromium 浏览器，模拟用户登录、加购、结算。如果 E2E 测试全绿，说明主业务流程在真实浏览器环境里坚不可摧。
* **部署上线**：将 `dist/` 文件夹整体丢进你的 1Panel 反向代理目录，或者打包成 Docker 镜像。因为是纯静态网页，配合 Nginx 并开启 Gzip 压缩，C 端用户打开你的购物首页将体验到丝滑的“秒开”速度。
